Méthode

D'où viennent les chiffres, comment les lire, et ce qu'il faut savoir avant de s'y fier.

D'où viennent les chiffres

Tout vient de sources publiques, consultées par programme, sauf l'étude de l'Apec, lue puis résumée. Aucune annonce n'a été copiée automatiquement sur LinkedIn, l'Apec ou Indeed, dont les conditions d'utilisation l'interdisent.

Comment lire les chiffres

  • Chaque chiffre a sa source, sa date et ses limites, indiquées juste sous le graphique ou le tableau. La date en bas de chaque page est celle de la dernière extraction.
  • Une offre enregistrée n'est pas un recrutement. Les offres comptées par France Travail ne sont qu'une partie du marché, et leur baisse ne signifie pas forcément que l'on recrute moins : les embauches enregistrées, elles, n'ont pas baissé.
  • Les nombres sont arrondis. Dans le Puy-de-Dôme, les volumes sont trop faibles pour être lus finement.
  • Les annonces forment un échantillon, pas l'ensemble du marché. Une annonce peut ne plus être en ligne quand vous cliquez dessus.
  • L'alternance est estimée d'après des mots dans le titre ou l'extrait de l'annonce : c'est un ordre de grandeur.

Ce qu'il faut savoir

  • Pas d'annonces complètes. L'accès aux offres officielles de France Travail n'était pas disponible pour ce projet. Les annonces viennent d'Adzuna, qui ne fournit qu'un extrait d'environ 500 caractères : les outils (HubSpot, SQL, Google Analytics…) ne peuvent donc pas être comptés sérieusement.
  • Une couverture partielle du Puy-de-Dôme. Seulement 2 annonces sur la période, contre plus de 350 en Île-de-France. Pour le département, le répertoire des entreprises est plus utile que les annonces.
  • Un classement d'entreprises incomplet. Le service qui classe les entreprises selon leur potentiel d'embauche (La Bonne Boite) n'a pas répondu : il n'est pas utilisé.
  • Peu de recul dans le temps pour les annonces. Une seule extraction complète est disponible, complétée par de simples relevés du nombre d'annonces à plusieurs dates.

Données personnelles

Ce site n'utilise aucun outil de suivi : pas de compte, pas de cookie publicitaire, pas de statistiques de visite. Il ne publie aucune donnée personnelle : seulement des entreprises, jamais de noms de dirigeants ni de contacts nominatifs. Les coordonnées d'une entreprise se trouvent sur sa fiche officielle, vers laquelle le site renvoie. Toute prise de contact avec une personne relève de la règle suivante : une finalité claire (par exemple une candidature), en lien avec sa fonction, avec possibilité de s'opposer.

Pour vérifier ou reproduire

Le projet est entièrement ouvert : le code, les données et les réponses d'origine des services sont publiés.

Les fichiers et les scripts
  • scripts/marche_du_travail.ps1 : offres par trimestre → data/marche_travail_AAAA-MM-JJ.csv.
  • scripts/indicateurs_marche.ps1 : tension, embauches, salaires → data/indicateurs_AAAA-MM-JJ.csv.
  • scripts/rome.ps1 : appellations et compétences → data/rome_*.csv.
  • scripts/adzuna.ps1 : annonces → data/adzuna_offres_AAAA-MM-JJ.csv (sans le texte des annonces, qui est un contenu de tiers).
  • scripts/adzuna_compteurs.ps1 : relevé léger du nombre d'annonces, daté → data/adzuna_compteurs.csv.
  • scripts/completer_departement.ps1 : ajoute le département de chaque annonce, sans nouvelle requête.
  • scripts/entreprises63.ps1 : entreprises du Puy-de-Dôme → data/entreprises_63_AAAA-MM-JJ.csv, d'où est tiré le répertoire de la page Acteurs.
  • scripts/build_site.ps1 : prépare les données lues par les pages du site.
  • data/raw/ : les réponses d'origine des services, conservées pour vérifier chaque chiffre.
  • carte_regions.js, carte_departements.js, carte.js : la carte de la page Annonces. Contours simplifiés issus du dépôt public france-geojson (Grégoire David, données Etalab / IGN), coordonnées arrondies.

Chaque fichier de données porte la date de son extraction dans son nom : relancer un script crée un nouveau fichier daté.

Comment les données sont mises à jour

Les mises à jour sont lancées à la main, sans automatisation planifiée : on exécute les scripts, puis build_site.ps1 prépare les pages, et le tout est publié sur GitHub. Les identifiants des services sont dans un fichier .env qui n'est jamais publié. La clé Adzuna utilisée est une clé d'essai au quota limité : une extraction complète en consomme une trentaine, d'où l'usage de relevés légers (5 requêtes) entre deux extractions complètes.

Les services techniques utilisés

France Travail (API « Marché du travail », API « ROME 4.0 »), Adzuna (API de recherche d'offres), Recherche d'entreprises (API de l'État, base Sirene). Les services demandés mais non utilisés : « Offres d'emploi » de France Travail (absente du compte développeur) et « La Bonne Boite » (accès refusé malgré l'activation).
